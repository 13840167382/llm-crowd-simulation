## 1. P0：建议优先修复的问题

这些是**已确认的代码缺陷或数据一致性问题**，会直接影响交付数据的可用性。

| # | 问题 | 位置 | 影响 | 建议方案 |
|---|------|------|------|----------|
| 1 | **路径 CSV 强依赖渲染模式** | `HeatmapCompareOverlayRenderer.CachePathTracesForExport` | 实验期间若未进入 `PathTraces` 模式，导出结果为 `skipped(no_cached_data)`，**产物缺失** | 在 `TryCaptureHeatmapLayersOnCompleteAsync` 中**主动调用一次** `FetchAndRenderPathTracesAsync` 后再导出；或改为由 `TrajectoryBatchReporter` 每次上报时**旁路累积**轨迹点缓存，与渲染模式解耦 |
| 2 | **`SetAllAgentsVisibleInScene` 参数被忽略** | `DecisionBatchScheduler.SetAllAgentsVisibleInScene(bool visible)` | 无论传入 `true` 还是 `false`，内部恒调用 `SetAgentRenderersVisible(false)`，**无法恢复显示** | 把实现改为 `point.SetAgentRenderersVisible(visible)`；并在截图中断/重试路径上补一次恢复调用 |
| 3 | **Agent ID 存在两套格式** | `ResolveEffectiveAgentId` vs `AgentId` / CSV 导出 | 决策日志中为 `agent_0001#12345`，轨迹 CSV 与后端数据中为 `agent_0001`，**无法直接关联** | 二选一：① 决策日志也输出纯 `agent_id`（`#InstanceID` 仅作内部 key）；② 在 CSV 中额外增加 `scene_instance_id` 列并同时输出纯净 `agent_id` |
| 4 | **出口匹配使用零点作为参考位置** | `DecisionBatchScheduler.ResolveExitIdToZone` 中 `TryGetNearestExitBySourceZone(normalizedCurrent, Vector3.zero, ...)` | 当同一源区域存在多个通往同一目标区域的出口时，**总是选中「离世界原点最近」的那个**，与 Agent 实际位置无关，可能导致绕路 | 改为传入 Agent 的真实世界坐标（`point.transform.position`），或优先按 `pass_capacity_per_sec` 选择 |
| 5 | **决策日志无上限增长** | `decisionTranscriptLines`（初始容量 4096） | 长时间实验（数小时、批次数千）下内存持续增长，且导出文本文件可达数十 MB | 增加 `maxTranscriptLines` 配置，超出后按批**滑动丢弃最旧批次**；或改为**流式追加写入**文件而非内存累积 |

## 2. P1：架构与可维护性

| # | 问题 | 现状 | 建议 |
|---|------|------|------|
| 6 | **巨型类** | `DecisionBatchScheduler` ≈ 3400 行、`DecisionAgentPoint` ≈ 2000 行、`HeatmapCompareOverlayRenderer` ≈ 1850 行 | 按职责用 `partial` 拆分，例如调度器分为：`Dispatch`（派发主流程）/ `Collect`（采集）/ `Override`（覆写）/ `Transcript`（日志）/ `Log`（调试输出）/ `Utils`（工具函数），每部分独立文件 |
| 7 | **残留死代码** | `HeatmapCompareOverlayRenderer.ClientProvided()` 为空方法，内部是近百行注释掉的 JS 代码；`DecisionAgentPoint` 中疑似存在未使用方法 | 直接删除，避免误导后续维护者 |
| 8 | **频繁 `FindObjectsOfType`** | `ExperimentManager`、`HeatmapCompareOverlayRenderer`、`TrajectoryBatchReporter` 中多处调用 | `DecisionBatchScheduler` 已有 `reportedAgentPoints` 注册表，建议统一改为**注册表查询**，并在 `OnDestroy` 反注册；`FindObjectsOfType` 仅在回退路径保留 |
| 9 | **魔法数字与硬编码中文** | 评分默认值、日志格式串、`"(unknown_zone)"` 等散落各处 | 抽到 `static readonly` 常量或 `ScriptableObject` 配置资产；日志格式统一走格式化模板 |
| 10 | **场景切换后的状态残留** | `App` 为 `DontDestroyOnLoad`；切图后 `ExperimentManager` 的运行时状态依赖手动 `ResetRuntimeState` | 在 `HandleSceneLoaded` 中自动调用一次运行时状态重置（调度器、渲染器、上报器一并重置） |

## 3. P2：数据与分析能力

| # | 建议 | 价值 |
|---|------|------|
| 11 | **决策日志增加 JSONL 并行输出** | 当前 `.txt` 面向人工阅读。增加 `transcript_*.jsonl`（每行一个决策对象）可**直接接入 pandas / Jupyter** 做统计与出图 |
| 12 | **CSV 补充上下文列** | 现仅 5 列。建议追加 `crowd_type`、`zone_id`、`state`、`chosen_exit_id`、`confidence`，便于按人群类型/区域切片分析 |
| 13 | **热力图导出元数据** | 截图旁输出 `meta.json`（网格原点、单元大小、行数、列数、metric、normalization、时间窗口），保证图片可**复原数值含义** |
| 14 | **运行期指标采集** | 记录每批次的请求数/返回数/回退数/耗时/决策来源分布，产出**决策质量报告**（LLM 采纳率、平均置信度、区域负载曲线） |
| 15 | **实验对比视图** | 支持把两次实验（如「纯 LLM」vs「本地算法」）的轨迹与热力图叠加对比 |

## 4. P3：性能与扩展性

| # | 建议 | 说明 |
|---|------|------|
| 16 | **热力图图层复用** | 目前每帧刷新后会 `Destroy` 重建 `Texture2D`。建议按尺寸复用纹理，仅 `SetPixels + Apply` |
| 17 | **决策结果批量应用优化** | `ApplyDecisionResultsAsync` 已有时间片预算，可进一步用 **Jobs/Burst** 处理评分计算，把 `LocalCrowdDecisionEngine` 的 5 维评分并行化 |
| 18 | **Agent 数量上限压力测试** | 当前 `maxAgentsPerBatch=64`。建议做 200 / 500 / 1000 Agent 的压测，确定帧率与后端吞吐的**拐点**并写入文档 |
| 19 | **后端 409 实验级锁优化** | LLM Only 模式下为避免 `decision_request_inflight` 需串行化，吞吐受限。建议后端改为**批次级幂等**而非实验级锁，或支持多批次并行合并 |
| 20 | **离线队列与断线重连** | 网络抖动时决策请求直接失败并进入冷却。建议引入**本地请求队列 + 指数退避重放**，并在 UI 上显示连接状态 |
| 21 | **动态区域容量** | `capacity` 目前为静态配置。可扩展为运行时可调（如按楼梯宽度、闸机开合状态动态变化） |

## 5. 工程化与质量保障

| # | 建议 | 说明 |
|---|------|------|
| 22 | **单元测试补全** | `Tests/` 目录已有框架。建议优先覆盖：① `LocalCrowdDecisionEngine` 评分公式（含边界条件）；② `TopologySceneConfig.TryBuildTopologyRequest` 的异常分支；③ DTO 的 `JsonUtility` 序列化/反序列化；④ `ResolveExitIdToZone` 匹配逻辑 |
| 23 | **拓扑配置静态校验** | 在 `TopologySceneConfig.OnValidate` 中做**编辑器期校验**：重复 `zoneId`/`exitId`、悬空 `targetZonePoint`、无 `isEntryZone`、无 `ExitFinal`、`FixedPathConfigSO.zoneIds` 引用了不存在的区域 —— 直接在 Console 报 `LogError`，避免运行时才发现 |
| 24 | **参数变更留痕** | 关键参数（`dispatchMode`、评分权重、`FixedPathConfigSO`）在实验开始时**写入日志或元数据**，便于结果复现与溯源 |
| 25 | **配置版本号** | 为 `CrowdDefaultProfile`、`TopologySceneConfig`、`FixedPathConfigSO` 增加 `version` 字段，交付后便于识别配置差异 |
| 26 | **LLM Provider 健康检查** | 多 Provider 轮询时，Key 过期（403）只会在运行时暴露。建议增加**启动自检**：逐个 Provider 发一次轻量请求，失败则告警并跳过 |
| 27 | **构建与打包脚本** | 固化 Unity 批处理构建命令（`-batchmode -quit -executeMethod`），产出可复现的交付包 |

## 6. 功能扩展方向

| 方向 | 说明 |
|------|------|
| **实验暂停/恢复** | 支持暂停仿真、查看中间态、再继续，便于现场演示与调试 |
| **参数面板化** | 把评分权重、`dispatchMode`、覆写配置做成运行时可调的 UI 面板，免去改 Inspector → 重运行 |
| **多方案 A/B 对比** | 同一地图、同一出生种子下，跑多组决策策略并自动对比指标 |
| **决策可解释性可视化** | 在 Scene 视图用箭头/颜色实时显示每个 Agent 的候选出口评分与选中原因 |
| **人群类型模板在线编辑** | 目前已有 `CrowdTypeTemplateManagementPanel`，可扩展为支持**批量导入/导出 JSON**，提升配置效率 |
| **后端分析接口对接** | 把后端已有的分析能力（区域负载曲线、排队时长分布）在 Unity 侧做成图表面板 |
