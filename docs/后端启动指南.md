# 后端启动指南（本地联调用）

本文档用于快速启动本项目后端，供 Unity 联调使用。

## 1. 前置条件

请先确认本机已安装：

- Python 3.12+
- PostgreSQL 16
- Redis
- TimescaleDB 扩展

macOS（Homebrew）示例：

```bash
brew install python@3.12 postgresql@16 redis
brew services start postgresql@16
brew services start redis
```

## 2. 首次初始化（只需执行一次）

以下命令默认在仓库根目录执行。

### 2.1 创建虚拟环境并安装依赖

```bash
/opt/homebrew/bin/python3.12 -m venv backend/.venv
backend/.venv/bin/python -m pip install -U pip
backend/.venv/bin/python -m pip install -e "backend[dev]"
```

### 2.2 准备环境变量

```bash
cp backend/.env.local.example backend/.env.local
```

如你已经有 `backend/.env.local`，可跳过本步骤。

### 2.3 初始化数据库与 TimescaleDB 扩展

请将下方用户名、密码、数据库名改成你本地实际值。

```bash
psql -h 127.0.0.1 -U postgres -d postgres -c "CREATE DATABASE crowd_flow_simulation_local;"
psql -h 127.0.0.1 -U postgres -d crowd_flow_simulation_local -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"
```

### 2.4 执行数据库迁移

```bash
cd backend
APP_ENV=local PYTHONPATH=.. .venv/bin/python -m alembic -c alembic.ini upgrade head
```

## 3. 启动后端进程

需要两个终端窗口，分别运行 API 与 worker。

### 3.1 启动 API

```bash
cd backend
APP_ENV=local PYTHONPATH=.. .venv/bin/python -m backend
```

默认地址：`http://127.0.0.1:8987`

### 3.2 启动 maintenance worker

```bash
cd backend
APP_ENV=local PYTHONPATH=.. .venv/bin/python -m backend run-maintenance-worker --without-scheduler
```

## 4. 启动后验证

### 4.1 健康检查

```bash
curl http://127.0.0.1:8987/healthz
curl http://127.0.0.1:8987/healthz/db
curl http://127.0.0.1:8987/healthz/redis
```

### 4.2 业务接口 smoke test

```bash
curl -H "X-Request-Id: local-smoke-001" http://127.0.0.1:8987/api/v1/crowd-types
```

如果返回 `code=0` 且 `items` 有数据，说明 Unity 可以开始联调。

## 5. 停止服务

- API 终端按 `Ctrl+C`
- worker 终端按 `Ctrl+C`
- 若需要停止依赖服务：

```bash
brew services stop redis
brew services stop postgresql@16
```

## 6. 常见问题

### 6.1 No module named backend

原因：在 `backend` 目录直接运行 `python -m backend`，但没设置 `PYTHONPATH=..`。

解决：按本文命令使用：

```bash
APP_ENV=local PYTHONPATH=.. .venv/bin/python -m backend
```

### 6.2 项目依赖安装失败（Python 版本不满足）

项目要求 Python >= 3.12。请先用 Python 3.12 重建虚拟环境。

### 6.3 数据库健康检查提示 timescaledb 不可用

请确认目标数据库已执行：

```sql
CREATE EXTENSION IF NOT EXISTS timescaledb;
```

### 6.4 决策批次全部 fallback

如果 Unity 日志里出现类似下面的结果：

```text
[DecisionBatchScheduler] Decision batch sent. batch_id=..., requested=4, returned=4, success=0, fallback=4
```

通常不是 Unity 批量大小或调度并发的问题，而是模型服务链路不可用。已确认过的典型现象包括：

- 后端日志出现 `Remote end closed connection without response`
- 后端日志出现 `决策模型连接失败: timed out`
- 直接请求 `${APP_DECISION_PROVIDER_BASE_URL}/chat/completions` 返回 `Empty reply from server`

建议先在后端机器上做直连探测，确认模型服务可以稳定返回 HTTP 200，再继续排查 Unity 侧：

```bash
curl -v -m 8 \
	-H "Authorization: Bearer $APP_DECISION_PROVIDER_API_KEY" \
	-H 'Content-Type: application/json' \
	"$APP_DECISION_PROVIDER_BASE_URL/chat/completions" \
	--data '{"model":"qwen36-fp8","messages":[{"role":"user","content":"ping"}]}'
```

如果这里仍然是空响应，优先修复模型服务地址、隧道或反向代理，而不是继续调 Unity 批次参数。
