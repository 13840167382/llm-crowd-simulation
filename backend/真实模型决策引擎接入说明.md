# 真实模型决策引擎接入说明

本地 vLLM + Qwen3.6-35B-A3B 的部署命令、环境变量及 Unity 设置见 [本地大模型接入指南](../docs/LOCAL_LLM.md)。本文件主要说明接口和服务内部行为。

## 当前结构
当前决策模块已经拆成了 4 层：

- [engine.py](<app/application/decisions/engine.py>)
  负责统一接口、异常定义和引擎工厂
- [prompt_builder.py](<app/application/decisions/prompt_builder.py>)
  负责按约定格式组装 Prompt
- [response_parser.py](<app/application/decisions/response_parser.py>)
  负责严格解析模型 JSON 输出
- [llm_engine.py](<app/application/decisions/llm_engine.py>)
  负责真实模型 HTTP 调用

业务编排仍在：

- [service.py](<app/application/decisions/service.py>)

模型调用、Prompt 组装、响应解析和业务编排已经分层，主流程不直接绑定某一个模型提供方。

## 默认模式
代码常量中的默认值为真实模型兼容模式：

```env
APP_DECISION_ENGINE_MODE=openai_compatible
```

发布仓库的 `.env.local.example` 为便于首次联调设为 `heuristic`；复制该模板后，必须显式改为 `openai_compatible` 才会调用模型。需要填写非空的 `APP_DECISION_PROVIDER_API_KEY`，即使模型服务在本机也一样。离线联调、单元测试或纯后端压测可保留 `heuristic`。

当前支持的模式名：

- 真实模型兼容模式：`openai_compatible`、`openai`、`llm`
- 本地启发式模式：`heuristic`、`mock`、`local`

这里的 `local` 是启发式算法的别名，不会加载或调用本地模型。

## 切到真实模型模式
真实模型配置通过环境变量控制：

```env
APP_DECISION_ENGINE_MODE=openai_compatible
APP_DECISION_PROVIDER_BASE_URL=https://api.openai.com/v1
APP_DECISION_PROVIDER_API_KEY=你的密钥
APP_DECISION_PROVIDER_MODEL=
APP_DECISION_PROVIDER_TEMPERATURE=0
APP_DECISION_PROMPT_VERSION=v1
APP_DECISION_BATCH_MAX_CONCURRENCY=4
```

说明：

- `APP_DECISION_PROVIDER_MODEL` 如果留空，会优先使用实验配置里的 `llm_config.model`
- 当前实现走的是 OpenAI Chat Completions 风格接口
- 请求路径固定为 `{APP_DECISION_PROVIDER_BASE_URL}/chat/completions`
- 请求体包含 `response_format: {"type": "json_object"}`
- 只要目标服务兼容这套接口，也可以直接复用
- `APP_DECISION_BATCH_MAX_CONCURRENCY` 用来控制单个决策批次里最多并行发起多少个 LLM 调用；如果设为 `1`，就会退回串行模式

## Prompt 组装策略
当前 Prompt 已按如下思路落地：

- 系统提示固定约束：
  只能从候选出口中选一个 `chosen_exit_id`
  只能输出 JSON
  `reasoning` 必须是一句话
  `confidence` 必须在 `0.0 ~ 1.0`
- 用户提示会注入：
  - 人物类型显示名
  - 困境摘要
  - 耐心消耗百分比
  - 算法推荐及对应评分
  - 全部候选出口、自然语言描述和算法评分

## 模型输出要求
当前解析器要求模型最终输出必须能被解析成：

```json
{
  "chosen_exit_id": "exit_xxx",
  "reasoning": "一句话理由",
  "confidence": 0.78
}
```

如果出现以下情况，会直接走 fallback 或 `none`：

- 不是合法 JSON
- 缺少 `chosen_exit_id`
- `chosen_exit_id` 不在候选出口中
- `confidence` 不是数字
- `confidence` 不在 `0.0 ~ 1.0`

## 错误码边界
按 PDF `5.1` 的批量决策降级策略，`POST /api/v1/experiments/{experimentId}/decisions` 的主路径不会把单人级 LLM 异常直接暴露成 `3001 / 3002 / 3003`：

- 单人模型调用失败或单人超时：该人物按 `fallback_to_algorithm` 返回 `fallback` 或 `none`
- 模型响应解析失败、非法 `chosen_exit_id`、非法置信度：该人物按 `fallback_to_algorithm` 返回 `fallback` 或 `none`
- 整批超过硬超时：已完成的人物正常返回，未完成的人物按 `fallback_to_algorithm` 返回 `fallback` 或 `none`

`3004` 仍是接口级错误：当决策引擎整体不可用，并且当前实验不允许 fallback 时，接口返回 `503 / 3004`。

## Provider 边界

当前真实模型调用集中在：

- [llm_engine.py](<app/application/decisions/llm_engine.py>)

服务层入口保持在：

- [service.py](<app/application/decisions/service.py>)

服务层承担：

- 批次幂等
- Redis 锁
- 实验级单飞控制
- 批次超时
- fallback
- 统计与写库

其中批次幂等不依赖 Redis：同一实验同一 `batch_id` 的最终事实来源是数据库唯一约束和 `decision_batches.response_payload`。Redis 锁用于在批次处理中提前挡住重复请求和同实验并发请求，避免重复执行真实模型调用。

## 当前并发策略

当前 `decisions` 服务已经支持“单批有限并发”：

- 一个 HTTP 批次仍然只对应一个 `batch_id`
- 批内人物会按 `APP_DECISION_BATCH_MAX_CONCURRENCY` 做有限并发
- 同一实验仍然只允许 `1` 个未完成决策请求
- 如果整批超过硬超时，尚未完成的人物会直接走 fallback/none

也就是说，当前已经不是纯串行逐个调用了，但也不会无限并发把模型服务打满。
